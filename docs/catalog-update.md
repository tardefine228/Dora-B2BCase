# Обновление перечня ПП № 1875 (каталога)

Каталог хранится в `DATA_DIR` двумя синхронными файлами:
`data.csv` (классификатор `catalog`) и `data.json` (ML-индексация). Оба
пересоздаются из загруженного файла, поэтому разъехаться они не могут.

## Регламент для команды

1. **Подготовьте файл** нового перечня:
   - CSV с разделителем `;` и колонками исходного формата
     (`record_id;appendix;position;name;okpd2;code_role;…`) **или**
   - JSON-массив объектов с теми же полями.
   - Обязательные поля: `name` (непустое, ≤500 символов) и `okpd2`
     (формат `NN.NN…`; для строк-исключений допустим пустой код с
     `code_role` «Не указан»/«Исключение» — они помечаются warning'ом).
2. **Сухой прогон** (файл проверяется, но не устанавливается):

   ```bash
   curl -X POST "http://localhost:8000/admin/catalog?dry_run=true" \
        -H "X-Admin-API-Key: $ADMIN_API_KEY" \
        -F "file=@new_catalog.csv"
   ```

   Ответ: `rows_total`, `rows_valid`, `errors[]` (блокируют установку),
   `warnings[]` (дубликаты, неожиданные приложения и т.п.).
3. **Установка** — та же команда без `dry_run`. Каталог заменяется атомарно
   (временный файл + rename), кэш классификатора сбрасывается сразу.
4. **Переиндексация** (если работаете в ML-режиме `CLASSIFIER_BACKEND=qdrant`):
   либо сразу `?auto_reindex=true`, либо отдельно `POST /admin/reindex`.
   Переиндексация пересобирает индекс в фоне и атомарно переключает алиас —
   поиск не прерывается.
5. **Проверка**: `GET /admin/catalog` (число строк, `sha256`), затем несколько
   контрольных запросов `POST /classify` и
   `EMBEDDER_BACKEND=tfidf VECTOR_SEARCH=true PYTHONPATH=api python eval/run_eval.py --sweep`
   (обновляет `eval/eval_report.md` — именно эта конфигурация в нём и записана).
   После смены каталога перемеряются **оба** записанных замера: размеченный набор
   (`eval/baselines/lexical.json`) и синтетический стресс-набор
   (`EMBEDDER_BACKEND=tfidf VECTOR_SEARCH=false PYTHONPATH=api python
   eval/specifier_stress.py --limit 150 --json eval/baselines/specifier_stress.json`).
   Второй показывает цену спецификаторов на строках, которых в разметке нет, —
   именно он ловит регрессии, невидимые на 201 строке.
   Если каталог изменился настолько, что артефакт перестал воспроизводиться,
   CI-шаг «Shipped artifacts match a rebuild» это покажет: пересоберите модель.

## Ограничения

- Размер файла ≤ 5 МБ, тело запроса ≤ `MAX_REQUEST_BODY_BYTES`
  (по умолчанию 1 МБ; увеличьте переменную для больших перечней).
- До 50 000 строк за раз.
- Ошибки (`errors`) блокируют установку; чтобы пропустить «битые» строки,
  исправьте файл — частичная установка сознательно не поддерживается.
- В Docker каталог лежит на volume `catalog_data` и переживает перезапуски.

## Валидация без API

```bash
python scripts/validate_catalog.py path/to/new_catalog.csv
```

(Тот же набор правил, что и на сервере; удобно для pre-commit/CI.)

## Если изменился состав позиций

- Проверьте `eval/labeled_examples.csv`: часть эталонных ответов может
  устареть (колонка `expected_okpd2`).
- Пересоберите лёгкие ML-артефакты (лексический реранкер и tfidf-эмбеддер
  обучаются на каталоге): `python scripts/build_model.py`.
- Правки товарных мостов — `ml/lexicon.py` (см. комментарии в файле).
