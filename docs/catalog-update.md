# Обновление каталога и источника

Каталог хранится в `DATA_DIR`: `data.csv` для классификатора и `data.json` для индекса. Загрузка пересоздаёт оба формата из одних строк. Каждый файл заменяется через временный файл и rename; это не единая файловая транзакция для всего пакета. До замены источник отключается, поэтому частичный сбой не позволяет показать старый текст как соответствующий новому каталогу. При сбое повторите загрузку полного исправленного ZIP.

## Пакет одной редакции

ZIP содержит в корне только:

- `data.csv` **или** `data.json`;
- `source_text.txt` в UTF-8 с маркерами `=== СТРАНИЦА 1 ===`;
- необязательный `metadata.json`, например `{"edition":"Редакция, проверенная оператором","source_url":"https://example.org/source"}`.

У включённых позиций укажите `pdf_page_start` / `pdf_page_end`. Все указанные страницы должны быть в тексте. Общий распакованный размер ограничен 20 МБ; каталог — 5 МБ и 50 000 строк. Вложенные пути и лишние файлы ZIP отклоняются.

Неизвестная дата редакции обозначается как неизвестная. Ссылка оператора не является подтверждением актуальности. Встроенная ссылка на первоначальную официальную публикацию также не удостоверяет актуальность загруженного текста.

## Порядок действий

1. Подготовьте каталог и распознанный источник из одной редакции, проверьте их содержание.
2. Задайте `ADMIN_API_KEY` в окружении приложения. Уберите `CATALOG_PATH`, если он переопределяет `DATA_DIR/data.csv`.
3. Выполните проверку без установки:

```bash
curl -X POST "http://localhost:8000/admin/catalog?dry_run=true" \
  -H "X-Admin-API-Key: ВАШ_КЛЮЧ" -F "file=@catalog.zip"
```

4. Установите той же командой без `?dry_run=true`. Каталоговый классификатор подхватит новые строки; кэш сбросится.
5. Проверьте `GET /admin/catalog` с ключом, контрольный запрос и `/source/{record_id}?format=html`.
6. Если состав каталога изменился, обучите модель на установленной версии и перечитайте артефакты:

```bash
docker compose exec api python scripts/build_model.py --models-dir /app/builtin_models
curl -X POST http://localhost:8000/admin/models/reload -H "X-Admin-API-Key: ВАШ_КЛЮЧ"
```

В локальном запуске: `python scripts/build_model.py`, затем тот же HTTP-запрос. Во время обучения приложение продолжает работать; запускайте переобучение вне демонстрации и контролируйте нагрузку. `calibrated: true` в readiness означает, что обученная модель соответствует установленному каталогу, а не что новая редакция прошла экспертную приёмку.

7. Для `CLASSIFIER_BACKEND=qdrant` запустите `POST /admin/reindex` после обучения и загрузки новых весов. Наблюдайте задачу по возвращённому `status_url`. Пока индекс не обновлён, новые позиции могут отсутствовать; устаревшие и исключённые записи отфильтровываются по актуальному каталогу.
8. Проверьте качество на отложенных запросах. При ошибке восстановите предыдущий полный пакет, модель и индекс. Копию предыдущего пакета хранит оператор.

## CSV/JSON без текста

Допускается для совместимости, но отключает ссылки на старые фрагменты: источник вернёт 503 до загрузки полного пакета. Не копируйте старый `source_text.txt` к новой редакции ради устранения этой ошибки.

`source_manifest.json` связывает каталог и текст контрольными суммами. Изменение любого файла после установки также отключает фрагменты. Оригинальный набор из репозитория без манифеста сохраняет обратную совместимость; его редакция явно не подтверждена.

## Эксплуатация

Приложение рассчитано на один процесс API. HTTP-лимит тела задаётся `MAX_REQUEST_BODY_BYTES` (по умолчанию 1 МБ); для более крупного ZIP задайте подходящий лимит заранее. Каталог в Docker сохраняется в `catalog_data`, обученные веса — в `reranker_data`.

Точное совпадение кода проверяется по включённым строкам. Исключения относятся к своей позиции; текстовые запросы без явного кода всё равно нуждаются в проверке специалистом.
