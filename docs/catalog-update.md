# Обновление перечня ПП № 1875 (каталога)

Каталог хранится в `DATA_DIR` двумя синхронными файлами:
`data.csv` (классификатор `catalog`) и `data.json` (ML-индексация). Оба
пересоздаются из загруженного файла, поэтому разъехаться они не могут.

## Доступ администратора

Задайте `ADMIN_API_KEY` в локальном `.env` и выполните `docker compose up -d`,
чтобы API получил настройку. Ключ нужен для всех запросов ниже; `.env` не хранится
в Git. При дальнейших обновлениях самого каталога перезапуск не требуется.

## Регламент для команды

1. **Подготовьте файл** нового перечня:
   - CSV с разделителем `;` и колонками исходного формата
     (`record_id;appendix;position;name;okpd2;code_role;…`) **или**
   - JSON-массив объектов с теми же полями.
   - Обязательные поля: `name` (непустое, ≤10 000 символов) и `okpd2`
     (например `22`, `22.29`, `22.29.29.190`; для строк-исключений допустим пустой код с
     `code_role` «Не указан»/«Исключение» — они помечаются warning'ом).
2. **Сухой прогон** (файл проверяется, но не устанавливается):

   ```bash
   curl -X POST "http://localhost:8000/admin/catalog?dry_run=true" \
        -H "X-Admin-API-Key: $ADMIN_API_KEY" \
        -F "file=@new_catalog.csv"
   ```

   Ответ: `rows_total`, `rows_valid`, `errors[]` (блокируют установку),
   `warnings[]` (дубликаты, неожиданные приложения и т.п.).
3. **Установка** — та же команда без `dry_run`. Каталог заменяется атомарно
   (временный файл + rename), кэш классификатора сбрасывается сразу.
4. **Переиндексация** (если работаете в ML-режиме `CLASSIFIER_BACKEND=qdrant`):
   либо сразу `?auto_reindex=true`, либо отдельно `POST /admin/reindex`.
   Переиндексация пересобирает индекс в фоне и атомарно переключает алиас —
   поиск не прерывается.
5. **Проверка**: `GET /admin/catalog` (число строк, `sha256`), затем несколько
   контрольных запросов `POST /classify` и
   `EMBEDDER_BACKEND=tfidf VECTOR_SEARCH=true PYTHONPATH=api python eval/run_eval.py --sweep`
   (обновляет `eval/eval_report.md` — именно эта конфигурация в нём и записана).
   После смены каталога перемеряются **оба** записанных замера: размеченный набор
   (`eval/baselines/lexical.json`) и синтетический стресс-набор
   (`EMBEDDER_BACKEND=tfidf VECTOR_SEARCH=false PYTHONPATH=api python
   eval/specifier_stress.py --limit 150 --json eval/baselines/specifier_stress.json`).
   Второй показывает цену спецификаторов на строках, которых в разметке нет, —
   именно он ловит регрессии, невидимые на 201 строке.
   Если каталог изменился настолько, что артефакт перестал воспроизводиться,
   CI-шаг «Shipped artifacts match a rebuild» это покажет: пересоберите модель.

## Короткая процедура: заменить перечень и вернуть прежний

Всё делается через API с `X-Admin-API-Key`, перезапуск контейнера не нужен.
Порядок рассчитан на человека без Python — обычный терминал или PowerShell.

**1. Сохраните копию того, что сейчас работает.**
Копия внутри контейнера тоже останется (снимок), но внешняя надёжнее: она не
пропадёт при пересоздании volume.

```bash
curl -H "X-Admin-API-Key: $ADMIN_API_KEY" \
     -o catalog-current.csv http://localhost:8000/admin/catalog/export
```

```powershell
# Windows PowerShell
curl.exe -H "X-Admin-API-Key: $env:ADMIN_API_KEY" `
  -o catalog-current.csv http://localhost:8000/admin/catalog/export
```

**2. Проверьте новый файл, ничего не меняя** (`dry_run=true` — путь по умолчанию
для первой попытки; ответ покажет `rows_valid`, `errors[]`, `warnings[]`).

```bash
curl -X POST "http://localhost:8000/admin/catalog?dry_run=true" \
     -H "X-Admin-API-Key: $ADMIN_API_KEY" \
     -F "file=@new_catalog.csv"
```

**3. Установите** — та же команда без `dry_run`. Ответ содержит `catalog.sha256`:
запишите его, по нему потом видно, какая редакция работает.

**4. Проверьте ответы** на двух-трёх контрольных позициях (`POST /classify`) —
каталог уже подхвачен, старых кэшей нет.

**5. Если новая редакция неверна — откат** (снимок сделан автоматически перед
загрузкой; кэши сбрасываются, ответы меняются сразу):

```bash
curl -X POST http://localhost:8000/admin/catalog/rollback \
     -H "X-Admin-API-Key: $ADMIN_API_KEY"
```

Ответ: `restored.version_id`, `catalog.rows`, `catalog.sha256`. Посмотреть, что
вообще есть, можно через `GET /admin/catalog/versions` (хранится
`CATALOG_SNAPSHOT_KEEP=10` последних снимков, старые удаляются).

Откат обратим: состояние, которое он заменяет, тоже снимается. Повторный откат
вернёт то, от чего вы только что отказались, — это удобно, если откатились по
ошибке. Если снимков нет (например, это самая первая загрузка) — ответ 409.

В ML-режиме (`CLASSIFIER_BACKEND=qdrant`) после загрузки и после отката нужна
переиндексация: `POST /admin/reindex` или `?auto_reindex=true` при загрузке.

## Ограничения

- Размер файла ≤ 5 МБ, тело запроса ≤ `MAX_REQUEST_BODY_BYTES`
  (по умолчанию 1 МБ; увеличьте переменную для больших перечней).
- До 50 000 строк за раз.
- Ошибки (`errors`) блокируют установку; чтобы пропустить «битые» строки,
  исправьте файл — частичная установка сознательно не поддерживается.
- В Docker каталог лежит на volume `catalog_data` и переживает перезапуски.

## Валидация без API

```bash
python scripts/validate_catalog.py path/to/new_catalog.csv
```

(Тот же набор правил, что и на сервере; удобно для pre-commit/CI.)

## Если изменился состав позиций

- Проверьте `eval/labeled_examples.csv`: часть эталонных ответов может
  устареть (колонка `expected_okpd2`).
- Пересоберите лёгкие ML-артефакты (лексический реранкер и tfidf-эмбеддер
  обучаются на каталоге): `python scripts/build_model.py`.
- Правки товарных мостов — `ml/lexicon.py` (см. комментарии в файле).


## Обновление всей редакции ZIP-пакетом

`POST /admin/catalog` также принимает ZIP с **ровно тремя файлами в корне**:
`data.csv`, `source_text.txt`, `report.json` из одного запуска парсера.
Произвольные вложенные пути, дубликаты файлов, несуществующие страницы,
повторяющиеся record_id, некорректный JSON и слишком большие архивы отклоняются.
Это структурная проверка согласованности, не юридическая экспертиза редакции.

```powershell
python scripts/parse_pp1875.py "C:\путь\pp_1875.pdf" --out "catalog-new"
Compress-Archive -Path "catalog-new/data.csv","catalog-new/source_text.txt","catalog-new/report.json" -DestinationPath "edition.zip"
```

В `/docs` авторизуйтесь ключом администратора и выберите ZIP в POST `/admin/catalog`.
Сначала выполните `dry_run=true`, проверьте errors и warnings; затем загрузите
с `dry_run=false` и `auto_reindex=true`. Проверьте applied, сведения GET
`/admin/catalog`, контрольную классификацию и страницу `/source/{record_id}`.
В режиме qdrant переиндексация остаётся отдельной фоновой операцией: дождитесь
её успешного завершения через существующий API статуса задания. Установка файлов
не означает успешного завершения индексации; при её ошибке доступен откат.

После загрузки пакета файлы лежат в неизменяемой папке `DATA_DIR/revisions/…`.
Файл `active-catalog.json` переключается атомарно только после записи всех файлов.
API, классификатор и загрузчик ML читают активную редакцию; старые корневые файлы
не являются текущим каталогом. Не редактируйте их вручную. Снимки и откат сохраняют
каталог, текст и отчёт вместе. Старые снимки без текста восстанавливаются без
подмешивания текста от более новой редакции.

CSV/JSON остаются совместимыми: они обновляют таблицу, сохраняя текущий текст.
Для новой редакции PDF всегда используйте ZIP. GET `/admin/catalog/export`
по-прежнему экспортирует только CSV, а не резервную копию всего первоисточника.
Для полной внешней копии сохраняйте исходный ZIP или весь том catalog_data.

Ограничения: ZIP до 5 МБ, суммарно распакованные файлы до 20 МБ; общий HTTP-лимит
MAX_REQUEST_BODY_BYTES тоже применяется (по умолчанию 1 МБ). Если пакет больше,
настройте лимит заранее. Неизменяемые папки revisions пока не удаляются автоматически,
чтобы не обрывать читающие старую редакцию процессы; учитывайте их объём при эксплуатации.

Само внедрение поддержки ZIP требует однократного обновления образа приложения.
Последующие загрузки редакций не требуют пересборки или перезапуска контейнеров.
