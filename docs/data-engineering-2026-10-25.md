## Результаты аудита

CSV и JSON совпадают после нормализации типов (булево True и текст true эквивалентны; None и пустая строка эквивалентны). Уникальные record_id сохранены. Нет разъехавшихся полей, лишних JSON ID или повторяющихся ID.

1119 строк имеют роль «Включён», одна — «Исключение», шесть — «Не указан». Повторы кода и имени перечислены группами ID в catalog_audit.json. Они не удалены: одно наименование встречается в разных приложениях с собственными ссылками и условиями. review_required и длинные названия могут пересекаться, их нельзя суммировать как число уникальных дефектов.

Файл каталога и веса не изменены: подтверждённых новых текстовых исправлений в этом проходе нет. «Валидатор без предупреждений» не достигнут и не должен достигаться удалением законных строк или сокрытием предупреждений.

## Контракт полей данных

- record_id — стабильная идентичность исходной записи. Совпадение кода и имени не является достаточным основанием удалить запись из другого приложения.
- «Включён» — роль кода в извлечённой позиции. Не самостоятельное юридическое заключение о любой закупке.
- «Исключение» — сохранить роль и контекст. Код исключения нельзя интерпретировать как положительное подтверждение попадания в перечень.
- «Не указан» и пустой okpd2 — исходная запись сохраняется, код не придумывается и не используется как положительная обучающая метка.
- review_required=true — неподтверждённая запись, нуждается в сверке. Снять флаг можно только вместе с автором, датой, основанием и протоколом изменения CSV/JSON.
- Текущий classifier передаёт code_role и catalog_review_required как информационные поля; они не гарантируют автоматического понижения статуса. Этот пробел поведения не считается исправленным документированием.

Для названия real_queries.csv дополнительно подтвердите, что запросы действительно из закупок, а не синтетические.
