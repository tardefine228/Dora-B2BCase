## Найденные дефекты

### 1. CSV-выгрузка из 1С разбирается неверно — исправлено, нужен пересбор образа

В выдаче по `it_zakupka.csv` запросами стали целые строки файла:

```
"1;Ноутбук Lenovo ThinkPad T14;шт.;3;89 900"   → 26.20.11 ok
"№;Наименование товара;Ед. изм.;Кол-во;Цена"   → not_found   ← шапка как товар
```

Причина: `csv.Sniffer` на файле с разделителем `;` и десятичными запятыми
(`89 900,00`) отвечал «запятая», и строка не делилась на столбцы. Именно это
исправлено в `api/app/services/file_items.py` (`detect_csv_delimiter`: разделитель
выбирается по самой широкой согласованной таблице, ответ Sniffer — только тай-брейкер)
и закреплено тестом `test_semicolon_csv_with_decimal_commas_is_not_split_by_comma`.

**Вывод: контейнер собран из кода до этого исправления.** Нужен пересбор из ветки
`arena/cac9f511-dora-b2bcase`: `docker compose up --build -d`.

Побочный эффект того же дефекта — две позиции ушли в `not_found`
(«Источник бесперебойного питания 3000 ВА», «Картридж лазерный для принтера»):
мусорный запрос не мог совпасть ни с одной позицией перечня. Это не ошибка модели.

### 2. Заголовок Markdown принимается за товар — исправлено

```
"# Перечень позиций к закупке" → 22.22.1 «Изделия пластмассовые упаковочные» ok 0.81
```

Уверенный ответ по строке, которая является заголовком документа, — худший тип
ошибки: закупщик не увидит повода перепроверить. Теперь для `.md`/`.markdown`
заголовки (`# …`, `## …`) отбрасываются как структура документа и попадают в
счётчик `skipped`, а не в список товаров (`_read_text` + тест
`test_markdown_headings_are_structure_not_products`). Для `.txt` правило не
применяется: там `#` — обычный символ.

### 3. «Мясо говядина замороженная» → `not_found` — требует проверки на стенде

В перечне есть точная позиция «Мясо крупного рогатого скота (говядина и телятина)
замороженное, в том числе для детского питания» (`10.11.31`). На эталонном
артефакте репозитория запрос уверенно попадает в неё (`ok`, 0.93), на стенде —
`not_found` при нулевой уверенности.

Стенд считает другими числами, чем эталонный артефакт: например,
«Ноутбук Lenovo ThinkPad T14» — 0.994 против 0.992, «Халат медицинский» — 0.938
против 0.939. Это ожидаемо, если образ собран с `INSTALL_TRANSFORMER=true`:
`scripts/build_model.py --dense --gate` переобучает реранкер с плотными признаками
и пересчитывает пороги `ok`/`review`.

Что проверить на стенде:

```powershell
Invoke-RestMethod http://localhost:8000/health/ready | ConvertTo-Json -Depth 4
```

* `vector_search.embedder` — должен быть `sentence-transformers/multilingual-e5-small`,
  а не `spacy-ru_core_news_md`;
* имя активного артефакта реранкера (`reranker.<тег>.json`) и его пороги;
* `ALLOW_DEGRADE` — при `true` разрешена тихая подмена эвристическим скорингом.

Если после пересборки позиция всё равно уходит в `not_found` — это регресс порогов
плотной сборки, его надо разбирать отдельно (разметка `eval/labeled_examples.csv`
плюс `eval/threshold_sweep.py`).
