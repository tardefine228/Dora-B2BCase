# Четыре новые выгрузки реального трафика (2026-10-26)

Пользователь прислал `classification-results (18)…(21).csv` — по 100 строк в каждом,
**400 уникальных запросов, ноль дублей, ноль пустых**. Все колонки вердиктов
(`user_verdict`, `corrected_code`, `verifier`, `verifier_note`) пустые: это журналы
классификации, а не разметка. Исходные файлы сохранены в
`eval/raw-exports/2026-10-26/` (CRLF, байт-в-байт; в `.gitattributes` для этой папки
отключена нормализация концов строк, чтобы sha256 оставался проверяемым).

## Что сделано пайплайном

1. **Очередь разметки DA-1.** `scripts/audit_data.py` построила пакет
   `eval/data-review-2026-10-26/`: `query_review.json` на 400 запросов
   (`label_kind: unlabeled`, поля `reviewer/reviewed_at/evidence` пустые), аудит каталога,
   реестр из 245 мостов, 41 `unclear`. С прошлыми двумя выгрузками (125 запросов в
   `eval/data-review-2026-10-25/`) пересечений нет — материал полностью новый.
2. **Майнер вердиктов отказался изобретать сигнал.** На объединённом экспорте
   `python -m ml.hard_negatives … --min-pairs 300` вернул 0 пар, диагноз
   «журнал классификаций, а не разметка» и код 1 по DoD ML-4. Так и должно быть:
   обучаться нечему, пока специалист не проставил вердикты.
3. **Дрифт текущей сборки.** `eval/real_traffic_check.py` переигрывает все 400 запросов
   текущей боевой конфигурацией (tfidf + векторные признаки) и сверяет с записанными в
   файлах ответами. Отчёт — `eval/real-traffic-2026-10-26.md`, машиночитаемая версия —
   `eval/data-review-2026-10-26/traffic_drift.json`.

## Что показал дрифт

| Метрика | Значение |
| --- | --- |
| Полностью неизменных ответов (код + статус) | **353 / 400** |
| Смен кода | 38 |
| Статусы в выгрузке → сейчас | `ok` 163 → 168, `review` 172 → 194, молчание 65 → 38 |
| Переходы | `not_found→review` 25, `review→ok` 7, `ok→review` 4, `not_found→ok` 2 |
| Сдвиг уверенности на неизменных ответах | медиана 0.015, максимум 0.114, точных совпадений 0 |

Нулевые совпадения уверенности означают, что выгрузки сделаны **более старой сборкой**
(до волн лексикона и пересборки артефактов 2026-10-25), поэтому сравнение честно показывает
накопленную разницу, а не шум одного релиза.

Природа изменений (проверено по каталогу):

* **25 переходов `not_found→review` — это слабые подсказки, не уверенные ответы.** У 23 из
  них уверенность ниже 0.7 (диапазон 0.28–0.67): модель теперь показывает кандидата, но
  статус `review` прямо требует проверки человеком. Так работает правило слабой подсказки
  (эксп. 34), а не рост разговорчивости ценой ошибок.
* **Два `not_found→ok` — вероятно, настоящие починки.** Обе строки — поваренная йодированная
  соль, новый код `10.84.30.130`; в каталоге это дословная позиция «Соль пищевая поваренная
  йодированная», уверенность 0.91.
* **`ok→review` для коньков — сработала политика «ложный код дороже молчания».** Старая
  сборка отвечала `15.2` («Обувь») статусом `ok`; текущая даёт `32.30.11.131`
  («Коньки ледовые, включая коньки с ботинками») статусом `review` при 0.64. Код стал
  точным, но уверенность намеренно осторожной.
* **Спорные замены внутри `review` отданы специалисту.** Например, электрокардиограф:
  `26.60.12.111` («Электрокардиографы») заменён на `27.20.22` («Аккумуляторы свинцовые») при
  0.48 — кандидат похож на ошибку. Продовольственные подсказки (творог `10.51.4`, томаты
  `01.13.34`, говядина, свинина) ссылаются на реальные позиции перечня, но их соответствие
  закупке — предмет разметки, а не автоматики.

Лексический путь (`VECTOR_SEARCH=false`) на тех же запросах: 173 `ok` / 180 `review` /
47 молчания, 30 отличий кода от выгрузки. Векторный путь покрывает на 9 строк больше
(38 против 47 молчаний) — та же роль векторов, что и на размеченном наборе.

## Следующие шаги

1. Специалист размечает `query_review.json`: `label_kind` (`code`/`not_found`),
   `expected_okpd2`, `reviewer`, `reviewed_at`, `evidence`. Затем
   `python scripts/export_reviewed_queries.py eval/data-review-2026-10-26/query_review.json
   --output eval/real_queries.csv` — это и есть закрытие DA-1.
2. На размеченных строках переснять recall@25 (ML-5) и метрики `run_eval.py` — впервые на
   реальных, а не синтетических запросах.
3. Вердикты, проставленные кнопками в UI и выгруженные через `/admin/feedback/export`,
   идут в `ml.hard_negatives`; DoD ML-4 — 300 пар — теперь упирается только в количество
   размеченных «неверно»/«нет в перечне».
4. Две строки `not_found→ok` (соль) и спорный электрокардиограф — первые кандидаты на
   разметку: они дешевле всего подтвердят или опровергнут дрифт.

## Воспроизведение

```bash
# очередь разметки и аудит
PYTHONPATH=api python scripts/audit_data.py \
  --exports eval/raw-exports/2026-10-26/*.csv --output eval/data-review-2026-10-26

# проверка, что майнер не видит сигнала в журнале без вердиктов
PYTHONPATH=api EMBEDDER_BACKEND=tfidf \
  python -m ml.hard_negatives <объединённый.csv> --min-pairs 300

# дрифт текущей боевой сборки
PYTHONPATH=api EMBEDDER_BACKEND=tfidf VECTOR_SEARCH=true python eval/real_traffic_check.py \
  --exports eval/raw-exports/2026-10-26/*.csv \
  --output eval/real-traffic-2026-10-26.md \
  --json eval/data-review-2026-10-26/traffic_drift.json
```
