# Закрытие технических долгов OPS-3 / OPS-5 / OPS-6 (2026-10-26)

Срез работ по аудиту `docs/audit-2026-10-20.md` и статусу
`docs/status-2026-10-25.md`. Сделано без внешних данных и доступов; все изменения
покрыты тестами, проверки CI расширены новой джобой.

## OPS-3 — явная деградация вместо тихой (закрыта)

**Было.** Build-аргумент `ALLOW_DEGRADE` уже ронял сборку образа при сбое ML-шага,
но в рантайме отсутствие калиброванного артефакта реранкера молча подменялось
`HeuristicReranker` с другими, неоткалиброванными порогами.

**Стало.**

- Та же переменная `ALLOW_DEGRADE` (по умолчанию `false`) проброшена в рантайм-окружение
  api и worker (`docker-compose.yml`, `x-app-env`).
- `app.services.classifier._load_reranker` в строгом режиме бросает
  `TrainedArtifactUnavailable`, если артефакт отсутствует, битый, пакет `ml.reranker`
  не импортируется или загрузчик вернул эвристику. Исключение переводит
  `/health/ready` в 503, healthcheck контейнера краснеет, счётчик
  `dora_classifier_up` = 0 → алерт `DoraClassifierDown`.
- `ALLOW_DEGRADE=true` сохраняет прежнее поведение для локальной диагностики —
  осознанно и с warning в логе.
- Явный выбор `EMBEDDER_BACKEND` и раньше не деградировал молча (цепочка фолбэков
  обрезается); режим `auto` логирует warning и виден через `dora_embedder_up`.
- Тесты: `api/tests/test_degradation_guard.py` (10 кейсов, включая интеграцию с
  `build_classifier` и mock-бэкенд).

## OPS-5 — бэкап/восстановление Postgres и лимиты памяти (закрыта)

- `scripts/pg_backup.sh` — gzip-дамп plain SQL (`--no-owner --clean --if-exists`),
  атомарная запись через `.tmp`, каталог `backups/` (в `.gitignore`), cron-пример в шапке.
- `scripts/pg_restore_check.sh` — восстановление в временную БД `dora_restore_check`,
  сверка ревизии alembic и количества строк во всех трёх прикладных таблицах,
  `ON_ERROR_STOP=1`, гарантированная очистка через `trap`.
- Новая CI-джоба `postgres-restore`: реальный PostgreSQL 16 (как в compose),
  миграции → запись строки → `pg_dump` → восстановление в отдельную БД → сверка.
  Регрессия процедуры ловится до целевой машины.
- Лимиты памяти собраны в `.env.example` целиком (`POSTGRES_*`, `REDIS_*`,
  `PROMETHEUS_*`, `GRAFANA_*`), дефолты совпадают с compose.
- Полный runbook: `docs/backup-restore.md`. Тесты: `api/tests/test_ops_scripts.py`.

## OPS-6 — JSON-логи, алерты, дашборд (закрыта)

- `LOG_FORMAT=json|text` (`app/core/log_config.py`): один JSON-объект на строку с
  полями `ts/level/logger/request_id/message`, трейсбеки в `exc_info`, `extra` —
  в отдельном поле. Compose по умолчанию отдаёт JSON; uvicorn-логгеры переведены на
  тот же форматтер. Тесты: `api/tests/test_logging.py`.
- Prometheus-правила `deploy/monitoring/prometheus/rules/dora-alerts.yml` — 7 алертов
  (готовность классификатора, деградация эмбеддера, недоступность Qdrant, доля 5xx,
  p95 > 1 с, провалы batch-задач, насыщение rate limit).
- Дашборд Grafana `deploy/monitoring/grafana/dashboards/dora.json` (HTTP-трафик,
  латентность p50/p95/p99, статусы классификатора, batch-события, готовность ML)
  с автоматическим провижинингом datasource и дашборда.
- Всё под опциональным compose-профилем `monitoring`
  (`docker compose --profile monitoring up`): базовый стек не меняется, порты только
  на loopback, конфиги монтируются read-only.
- Кросс-проверка: тест сверяет каждую метрику из правил и дашборда с реально
  экспортируемыми в `app/core/metrics.py` — переименование метрики не может молча
  обнулить панель. Тесты: `api/tests/test_observability_assets.py`.
- Runbook: `docs/observability.md`.

## DA-3 — ложные ошибки валидатора каталога (хвост закрыт)

- Шаблон `OKPD2_PATTERN` отвергал 731 валидную позицию (все коды финального уровня
  вида `22.29.29.190`): `^\d{2}(\.\d{1,2}){0,3}$` не допускал трёхзначный хвост.
- Заменён на грамматику ОКПД2 (ОК 034-2014):
  `XX | XX.X | XX.XX | XX.XX.X | XX.XX.XX | XX.XX.XX.XXX`. Шаблон строже к мусору
  (отвергает `22.29.29.19`, `22.29.190`, `99.9.9.999`) и принимает все 732 уникальных
  кода каталога.
- `validate_catalog.py`: было 752 ошибки / 393 валидных строки → стало **21 ошибка /
  1105 валидных**. Оставшиеся 21 — названия длиннее 500 символов (очередь ручной
  сверки PDF, DA-7; автоматически обрезать нельзя — теряются условия позиции).
  Снапшот источника даёт идентичный набор замечаний.
- Тесты: `api/tests/test_okpd2_validation.py`, включая регрессионную проверку каталога
  и снапшота.

## OPS-4 — фактически уже закрыта (статус приведён в соответствие)

CI содержит четыре зелёные джобы: `check`, `quality` (сборка/сверка артефактов и
quality gate), `frontend` (Vitest + Playwright, 3 e2e-сценария + доступность) и
`docker-smoke` (build образа + compose). После этой работы добавлена пятая,
`postgres-restore`. Отдельных действий не требует.

## OPS-7 — остаётся ручной (403 у интеграции)

API GitHub отвечает `403 Resource not accessible by integration` на чтение и запись
branch protection — у токена нет прав администрирования репозитория. Владельцу нужно
вручную: **Settings → Branches → Add branch ruleset / protection rule → `main`**:

1. Require a pull request before merging (1 approval);
2. Require status checks to pass: `check`, `quality`, `frontend`, `docker-smoke`,
   `postgres-restore`;
3. Require branches to be up to date before merging;
4. Do not allow bypassing the above settings (admin enforcement — по желанию).
