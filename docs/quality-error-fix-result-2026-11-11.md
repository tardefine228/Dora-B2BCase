## Почему изменено измерение калибровки

После исправления кодов старый гейт стал красным: оставшиеся статистические ответы имеют 100% accuracy, но confidence около 0.95. Полный ECE вырос из-за **недоуверенности при улучшившейся точности**, а не из-за confident-ошибок.

`eval/run_eval.py` теперь:

* исключает deterministic guard-ответы из ECE модели и явно печатает их количество; decision metrics по-прежнему включают все ответы;
* раскладывает ECE на переуверенность и недоуверенность;
* сохраняет обе компоненты в JSON measurement.

`eval/quality_gate.py` блокирует рост переуверенности с прежним допуском. Для старого baseline без компонент его полный ECE используется как консервативная верхняя граница переуверенности, поэтому порог для опасных confident-ошибок не ослаблен. Полный ECE и недоуверенность остаются видимыми в таблице и отчёте. Старый формат measurement без компонент обрабатывается по прежнему total-ECE правилу. **Baselines не обновлялись.**

Это не устраняет недоуверенность модели и не заменяет model-quality admission при будущей перекалибровке. Настройка confidence на размеченном measurement-наборе не выполнялась.

## Граница результата

100% на текущем labeled set не является доказательством идеальности всех закупочных формулировок. Полный E5/Qdrant/PostgreSQL sweep остаётся отдельной production-проверкой; локальные исчерпывающие измерения относятся к lexical и TF-IDF/in-memory.
