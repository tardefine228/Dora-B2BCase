## Исправления

- Общая проверка формата ОКПД2 принимает девятизначные коды в загрузке
  каталога и в точном поиске; отклоняет повреждённые коды.
- Лимит наименования каталога увеличен с 500 до 10 000 символов.
  Официальные длинные названия не обрезаются.
- Для `not_found` интерфейс и экспорт сохраняют числовую уверенность из API.
  Пояснение отличает уверенность в подборе кода от вероятности отсутствия товара.
- Приёмочный скрипт требует точности ≥85% и не менее 20 размеченных товаров,
  отдельно проверяет ≥17 правильных одиночных ответов из 20, скорость,
  полноту результатов, проценты и наличие ссылок у найденных кодов.
- Формат LF закреплён для артефактов с SHA-256 и shell-скриптов.
- Тесты PostgreSQL используют одну изолированную БД для задач, вердиктов
  и очистки журналов. В CI добавлен PostgreSQL, чтобы эти тесты не пропускались.

## Как повторить

Запустить Docker Desktop, затем из корня:

```powershell
docker compose up -d --build
docker compose ps
```

Интерфейс: http://localhost:8000/ui/.
Готовность и фактическая модель: http://localhost:8000/health/ready.

Для измерения без готовых ответов в памяти перезапустить API и worker,
дождаться готовности API, затем выполнить:

```powershell
python scripts/check_acceptance.py eval/labeled_examples.csv --output acceptance-report.json
```

Используются первые 100 уникальных строк существующего размеченного набора;
20 одиночных запросов выбираются из строк с ожидаемым кодом.
Коды сравниваются строго, без зачёта совпадений по общему префиксу.
Строки с `label_kind=unclear` или `absent` не входят в метрику точности кодов.
Повторный прогон может использовать кэш ответов; время загрузки модели при
старте приложения не входит во время запроса после готовности.

Это локальный контрольный набор проекта, а не неизвестный тест организаторов.
Результаты измерений подтверждают работу на указанной конфигурации, но не
обещают 100% точность на произвольных названиях.

Обновление каталога описано в [catalog-update.md](catalog-update.md).
Ключ администратора находится в локальном `.env`, который исключён из Git.
Ни рабочая БД, ни том каталога для проверки не удаляются.
