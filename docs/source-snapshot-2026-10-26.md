## 2. Снапшот перечня — сверка с рабочим каталогом

Снапшот сохранён как доказательство: `eval/source-snapshots/2026-10-26/pp_1875_dataframe.csv`
(1126 строк, 12 колонок; в `.gitattributes` для этой папки отключена нормализация концов строк,
байты зафиксированы). Сверку выполняет `scripts/verify_catalog_snapshot.py`, отчёты —
`verification.json` и `verification.md` в той же папке, контракт закрыт тестами
`api/tests/test_catalog_snapshot.py` (9 тестов).

### Результат: содержательно идентичен, замена не требуется

| Проверка | Результат |
| --- | --- |
| Число строк | 1126 / 1126, все id совпали после нормализации (`1-001-01` ≡ `1-1-01`) |
| Коды ОКПД2, роли, страницы PDF, подтверждающие документы, source-ячейки | **0 отличий** |
| Доли (min/max share) | 284 отличия только в формате (`80` vs `80.0`), расхождений значений **0** |
| Названия | 4 отличия — только позиция 402, и это наши исправления |
| Колонка `review_required` | есть только в рабочем каталоге (84 флага) — QA-метаданные, не часть перечня |

Четыре отличия в названиях ожидаемы и направлены в нашу пользу: снапшот содержит сырой OCR
(`объем контейнера 2 500 мл < 1000 мл), - - соответствующие…`), а каталог — текст после
визуальной сверки PDF от 2026-10-25 (`≥ 500 мл ≤ 1000 мл), соответствующие…`, см.
`docs/pdf-source-review-2026-10-25.md`). Идентификаторы этих строк (`2-402-1…4`) внесены в
whitelist верификатора: любое пятое текстовое расхождение или исчезновение ожидаемого
краснит тест.

Штатный `scripts/validate_catalog.py` на обоих файлах даёт одинаковые 752 замечания
(строгий шаблон кода отвергает длинные валидные коды вида `22.29.29.190`) — это известная
строгость валидатора (долг DA-3), а не дефект снапшота: наборы замечаний совпадают дословно.

### Почему каталог не заменяется снапшотом

1. Откат к сырому OCR в позиции 402 — потеря подтверждённой по PDF правки.
2. Исчезнут 84 флага `review_required` — очередь сверки первоисточника (DA-7).
3. Нулевая дополненность id (`1-001-01`) сломала бы ссылки `/source/{record_id}`, снапшоты
   версий каталога и тесты; выигрыш — косметический.
4. Ни одного нового кода, названия или страницы снапшот не содержит.

## 3. Границы вывода (что это НЕ доказывает)

Сверка подтверждает внутреннюю согласованность каталога с независимой выгрузкой того же
документа, но **не является сверкой действующей редакции ПП №1875** (задача DA-5 остаётся
открытой): дата вступления последующих изменений по первоисточникам не проверялась. Если
пользователь пришлёт обновлённую редакцию, путь такой: загрузка через `POST /admin/catalog`
(валидация, версия для отката), затем прогон верификатора — он явно покажет все новые
расхождения, а не только whitelist.

  --markdown eval/source-snapshots/2026-10-26/verification.md
