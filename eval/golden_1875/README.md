# Синтетический положительный набор ПП № 1875

Пять файлов `test_batch_1.csv` … `test_batch_5.csv`, по 100 записей без учета
заголовка. UTF-8, разделитель — запятая, кавычки по правилам CSV.
ОКПД2 необходимо читать как **строку**: ведущие нули значимы.

В каждом файле: 30 short (2–4 слова), 40 medium (товар и ключевые признаки),
30 long (не менее 20 разделенных пробелами токенов). Во всех файлах есть IT,
медтехника, одежда/текстиль, мебель/бытовая техника, канцелярия, транспорт,
электротехника/оборудование, стройматериалы/химия, музыка/спорт/игрушки, продукты.
500 различных названий: 100 видов товаров по пять вариантов с различающимися
характеристиками. Это не 500 разных кодов или 500 разных товарных категорий.
Названия синтетические, без заявлений о существовании конкретных SKU/брендов.

## Источник и семантика меток

Использованы `data/data.csv` и сохраненный текст `data/source_text.txt`.
Это фиксированный снимок источника из репозитория, а **не подтверждение актуальной
редакции постановления**. SHA-256 каталога, текста и исходного PDF (из отчета парсера)
зафиксированы в `manifest.json`. Все пары `(true_okpd2, appendix)` буквально есть
среди включенных строк каталога. Уточняющие дочерние коды, которых нет в каталоге,
не добавляются: `true_okpd2` означает **код позиции перечня**, в том числе укрупненный,
а не обязательно наиболее подробный девятизначный классификационный код товара.

Приложения 1/2 и приложение 3 решают разные правовые задачи (запрет/ограничение
и квота соответственно), поэтому не образуют взаимоисключающие классы.
`appendix` здесь — **приложение-источник выбранного кода**, а не утверждение, что
другие приложения неприменимы. Для скрипок/альтов/виолончелей выбраны точные коды
приложения 3, хотя приложение 2 покрывает их родовым кодом `32.20.12.110`.
Для компьютеров выбрано приложение 2, хотя они также фигурируют в приложении 3.
Не использовать единственную метку этого набора как юридическое доказательство
отсутствия других применимых режимов; в правовой модели нужны множественные метки.

`provenance.csv` содержит для каждой записи идентификатор исходной строки,
позицию, страницы PDF и исходное название. Для пяти отмеченных парсером позиций
(МРТ, кухонная мебель, саксофоны, охлажденное мясо птицы, йодированная соль)
сопоставление названия и кода дополнительно сверено с сохраненным текстом.
Глобальный статус отчета исходного парсера — `review_required`; этот набор
является кандидатом для golden dataset, а не заменой юридической экспертизы.

Только положительные примеры. Набор не измеряет способность отклонять товары
вне перечня или услуги. Варианты одного вида распределены между всеми файлами,
поэтому файлы — тестовые пакеты, **не независимые train/test разбиения**.
Не обучать модель на других пакетах перед оценкой оставшегося пакета.

## Воспроизведение и проверка

Из корня репозитория:

```sh
python eval/golden_1875/generate.py
python -m unittest discover -s eval/golden_1875 -p 'test_*.py' -v
```

Генератор детерминированный; `products.txt` хранит проверяемые шаблоны и пять
вариантов каждого вида. Проверяются схема, число строк, ID 1–500, уникальность,
пропорции длины, наличие всех трех приложений и точные пары код/приложение.
