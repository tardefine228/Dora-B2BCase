# Dora B2B — интерфейс первого спринта

React + TypeScript + Vite. Работает отдельно от Python, Docker и моделей.

## Установка

Нужен Node.js 22 LTS или новее с npm. Скопируйте содержимое этой папки в `frontend` общего репозитория. Файл `.gitkeep` можно оставить. Не создавайте вложенную папку `frontend/frontend`.

Из корня репозитория:

```bash
cd frontend
npm install
npm run dev
```

Откройте адрес, который напечатает Vite. Для остановки нажмите Ctrl+C.
Если PowerShell запрещает npm.ps1, используйте `npm.cmd install` и `npm.cmd run dev` или терминал Command Prompt. Менять политику PowerShell не требуется.

## Проверка

- Введите «Ноутбук Lenovo IdeaPad 15.6 дюймов»: увидите ожидание, затем пример карточки с 94%.
- Пустое название: понятная ошибка.
- Любой другой товар: сообщение об отсутствии демонстрационного ответа (это не вывод о наличии товара в перечне).
- Загрузите `examples/products.csv`, выберите столбец «Название товара», нажмите «Обработать список».
- Проверьте прогресс, таблицу, сортировку, скачивание Excel и удаление файла.
- Файл более чем со 100 строками товаров, неподдерживаемое расширение, пустое название в выбранном столбце: ошибка.
- `npm run build` проверяет TypeScript и создаёт сборку в dist.

## Формат входа

.xlsx или CSV UTF-8, до 5 МБ; первая строка — заголовки, далее 1–100 непустых строк товаров. Для Excel используется первый лист. Столбец выбирает пользователь. Пустые строки целиком пропускаются, пустые названия внутри выбранного столбца вызывают ошибку. Максимальная длина названия 500 символов. Старый .xls не поддерживается: сохраните как .xlsx. CSV с запятой, точкой с запятой или табуляцией распознаётся автоматически. Нет внешних шрифтов, CDN и API; после установки зависимостей демо работает без интернета.

## Что реализовано

Вёрстка по B2B.pdf; адаптация для телефона; ввод товара; чтение .xlsx/CSV и выбор столбца; демонстрационная обработка пачки; прогресс, сортировка и выгрузка .xlsx. Файлы обрабатываются в браузере, никуда не отправляются. Все коды и проценты — фикстуры, не ML-результаты. Ссылку не подделываем: в демо она отсутствует.

## Где менять код

- src/App.tsx — компоненты и состояния страницы.
- src/styles.css — оформление.
- src/files.ts — импорт и экспорт файлов.
- src/api.ts — интерфейс данных и mock-сервис.

## Подключение бэкенда

Пока весь api — mock. Согласовать с бэкендером:
1. POST /classify: тело запроса и ответ одного товара.
2. POST /classify/batch: принимает файл или JSON со списком, какие поля возвращает вместе с job_id.
3. GET /classify/batch/{job_id}: статусы, processed/total, формат результатов, ошибок и срок хранения задания.
4. Уверенность: число 0–1 или 0–100; ссылка на пункт, признак «требует проверки».
5. Адрес API и CORS / прокси.

После согласования заменить методы объекта api в src/api.ts на fetch с преобразованием ответа к типам Result и Job. Предусмотреть HTTP-ошибки, сетевой таймаут и серверный статус failed. Компоненты уже опрашивают getBatch последовательно с паузой 500 мс, прекращают опрос по завершении/ошибке или через 3 минуты. Это демонстрационный контракт, не утверждение о реальном формате API.

Для реального режима убрать/переключать демо-маркировку, добавить настоящую ссылку и критерии проверки. Не подменять ошибки настоящего API фиктивными успехами. Корневой docker-compose.yml не изменён — интеграцию согласуйте с ролью 4.

## Git

Работайте в feature/frontend. Добавляйте только frontend, не node_modules/dist. package-lock.json нужно коммитить. В архиве нет .git и зависимостей.
